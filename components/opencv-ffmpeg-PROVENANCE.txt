Corresponding source for the copyleft binaries inside opencv-python-headless
================================================================================

Why these archives are here
--------------------------------------------------------------------------------

opencv-python-headless 4.10.0.84 declares Apache-2.0, which is accurate for
OpenCV itself. The wheel also ships 63 prebuilt native libraries in
cv2/.dylibs/. Three of those components are GPL: FFmpeg (built with
--enable-gpl --enable-version3, so GPL-3.0-or-later), x264 and x265
(GPL-2.0-or-later). Thirteen more are LGPL or MPL-2.0 libraries that FFmpeg
links; they are listed under "The LGPL/MPL libraries" below.

We redistribute those binaries — they are inside the delivered numericEngine
executable — so the GPL, the LGPL and the MPL oblige us to make the
corresponding source available to the recipient. That obligation is discharged
by the written offer in section 3.0 of compliance/THIRD-PARTY-NOTICES.txt. The
archives named below are the source that offer provides; this file is the
record of how each was identified from the binary, and it is delivered with the
product so the identification can be checked without relying on the server the
archives came from.

The wheel's own cv2/LICENSE-3RD-PARTY.txt does not name x264 or x265 and
contains no GPL text, so it cannot be relied on as the notice for these.
See section 5.6 of compliance/THIRD-PARTY-NOTICES.txt.


How the versions were identified
--------------------------------------------------------------------------------

Not from an index lookup or from the wheel metadata, neither of which records
them. They were read out of the delivered binaries themselves, in

    numericEngine/app/_internal/cv2/.dylibs/

of the delivered build, which is arm64.

Not from a development virtualenv. This matters, and an earlier revision of
this file got it wrong: the same opencv-python-headless 4.10.0.84 release ships
DIFFERENT native libraries per architecture. The x86_64 (Intel) wheel carries
FFmpeg 7.0.1 and libx265.209; the arm64 wheel, which is the one delivered,
carries FFmpeg 6.0 and libx265.199. That earlier revision recorded the Intel
wheel's FFmpeg 7.0.1 and x265 3.5+1. Both are corrected below.

  FFmpeg   libavcodec.60.3.100.dylib. Its build-configuration string begins

               --prefix=/opt/homebrew/Cellar/ffmpeg/6.0_2 --enable-shared
               --enable-pthreads --enable-version3 ... --enable-gpl ...
               --enable-libx264 --enable-libx265 ...

           so the version is 6.0, Homebrew revision 6.0_2, and the build is the
           GPL one. The library's own avcodec_license() string reads
           "GPL version 3 or later". FFmpeg is LGPL-2.1-or-later by default;
           --enable-gpl makes the result GPL, and --enable-version3 makes it
           GPL-3.0-or-later.

  x264     libx264.164.dylib reports "r3108 31e19f9".
           r3108 is the revision, 31e19f9 the git commit.

  x265     libx265.199.dylib reports "3.4+31-6722fce1f": 31 commits past tag
           3.4, at commit 6722fce1f, API build 199.

The LGPL/MPL libraries
--------------------------------------------------------------------------------

FFmpeg in this build links thirteen further copyleft libraries, all bundled in
cv2/.dylibs/. Their source, the Homebrew formulas they were built from and the
patches those formulas apply are published under opencv-bundled/, and every
file is listed with its sha256 in opencv-bundled-MANIFEST.txt, which is
delivered with the product. Each archive and patch matched the sha256 its
formula records at homebrew-core commit 042325cd3852, retrieved 2026-10-29.

  gnutls 3.8.2          Homebrew Cellar path in the binary
                        LGPL-2.1-or-later
  nettle/hogweed 3.9.1  nettle_version_* API reports 3.9; patch level from
                        the formula. LGPL-3.0-or-later OR GPL-2.0-or-later
  gmp 6.3.0             version string. LGPL-3.0-or-later OR GPL-2.0-or-later
  libidn2 2.3.4         version string. LGPL-3.0-or-later OR GPL-2.0-or-later
  libunistring 1.1      _libunistring_version (0x0101)
                        LGPL-3.0-or-later OR GPL-2.0-or-later
  libtasn1 4.19.0       version string. LGPL-2.1-or-later
  gettext 0.22.4        Homebrew Cellar path in libintl. LGPL-2.1-or-later
  libbluray 1.3.4       "libbluray version" string. LGPL-2.1-or-later
  lame 3.100            version string in libmp3lame. LGPL-2.0-or-later
  soxr 0.1.3            "libsoxr-0.1.3" string. LGPL-2.1-or-later
  aribb24 1.0.4         INFERRED from the formula; the binary carries no
                        version. LGPL-3.0-or-later
  srt 1.5.3             library file name + formula. MPL-2.0
  zeromq 4.3.5          zmq_version() API. MPL-2.0

p11-kit is also in cv2/.dylibs/ but is BSD-3-Clause: attribution only.


Things stated rather than smoothed over
--------------------------------------------------------------------------------

1. These are pristine upstream sources plus the Homebrew formulas and patches
   for the identified versions. We did not build these binaries — the
   opencv-python project did, from Homebrew bottles on its own build machine.
   The FFmpeg formula is pinned to the commit that produced bottle 6.0_2; the
   bottles of the libraries it depends on may have been built at an earlier
   formula commit, but at the same upstream versions. The build-configuration
   string recovered above is recorded so that the build can be reconstructed.
   This limitation is inherent to redistributing someone else's binary build.

2. Two versions are inferred rather than read: aribb24 (the binary carries no
   version at all) and nettle's patch level (the API reports 3.9; 3.9.1 is
   what the formula of that date builds).

3. This directory addresses the SOURCE obligation for the components named
   above. Attribution for them, and for the other native libraries the OpenCV
   distribution bundles, is addressed in section 5.6 of
   compliance/THIRD-PARTY-NOTICES.txt.
